# Lane 3.6 Beam effectors, branch `calib/p3-beam`, model tag ids `de-dwell`, `hpm-field`, and the existing `jam` row's note

This lane fits a statistical estimate to a published datasheet value. Validation means the model reproduces the vendor number.

Lane 3.5 adds the projectile-group call on the same hook line; write yours as a separate statement so the merge is additive.

Deliverable (plan row 3.6). Optical effector: irradiance at range from `outputPowerKw`, `beamQualityM2`, `apertureM` and `jitterUrad` (diffraction-limited spot radius at 1070 nm times M squared, root sum square with the jitter spot, times a clear-air transmission from the environment visibility with one extinction constant and its source); dwell to threshold = the fluence to effect for the airframe class divided by irradiance, where the fluence constant per airframe class is calibrated so that the seed `dwellToEffectS` (Iron Beam, 2 s, quoted for its condition) is reproduced at its quoted range on a Group 1 quadcopter, and the other classes scale by a constant table you state with a source; slew and settle: one constant settle time per engagement with its source. The dwell is one event: one draw keyed at the commit step (a lognormal spread on the fluence, sigma from the field spread or PF_SPREAD) and one `clock.requestFineStep(effectorId, t, t + dwellS, 0.1)` so the dwell timeline samples at 0.1 s. RF field effector: field level at range from `fieldStrengthVm` at `fieldStrengthRangeM` by inverse distance, inside `beamwidthDeg`; effect when the field exceeds the effect threshold per airframe class (a constant table with its source; the seed does not hold one); `rechargeS` is the cooldown between engagements (it replaces `salvoCooldownS` for the RF field effector when present). Jam-to-signal: `ewPhysics.ts` reads the target UAS link budget from lane 3.2's `src/analysis/rfLink.ts` (merged on main before you started; read its exports) so the jammer's J/S at the target UAS receiver uses the same radiated power, path loss and band centre as detection; keep `assessJam`'s result shape and `effectiveJamRangeM` bit-identical when the target UAS has null `radiatedPowerW` (the band-overlap and EIRP path stays).

Fallback: the `legacyBeamPk` switch, or an optical effector with null `outputPowerKw`, or an RF field effector with null `fieldStrengthVm`, keeps today's `kineticPk` formula bit for bit on that effector.

Stop condition: dwell for an advertised power and range matches a hand computation (the test comment computes the spot, irradiance and dwell for one seed optical source at one range and pins them); the RF field effector ring at threshold equals the hand-derived range; `assessJam` unchanged on the null-power path. Validation tier: `datasheet` for the optical effector (the Iron Beam anchor), `analytic` for the RF field effector.
